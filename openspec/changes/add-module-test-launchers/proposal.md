# Proposal: 增加知识管线模块测试启动脚本

## 目标

- 在 `knowledge_pipeline/test/` 提供现有知识管线模块的独立启动脚本。
- 使用当前源码中的真实 CLI/API 契约，覆盖 PDF 解析、切片、索引、嵌入、词法/混合检索、语义检索、重排和生成上下文。
- 为每个脚本固定一个只读输入和隔离输出位置，并打印耗时、状态、输出路径和关键统计。
- 提供一个端到端串联脚本，验证从 PDF 到生成上下文的实际文件链路。

## 范围

- 新增文件仅位于 `knowledge_pipeline/test/`，以及本变更的 OpenSpec 文档。
- 测试输入使用项目中已有 PDF；中间产物写入 `knowledge_pipeline/test/results/`。
- 脚本只调用现有 `knowledge_pipeline` 模块，不复制解析、切片、索引、检索或生成逻辑。
- 解析脚本默认不启用远程视觉增强；如需 Responses API，应由现有模块配置和显式参数控制。

## 非目标

- 不修改任何生产知识库、活动 manifest、解析算法或检索算法。
- 不把脚本扩展为新的 benchmark/评测框架；耗时与摘要仅用于启动后核验。
- 不要求语义模型必须已下载；语义索引脚本在依赖缺失时给出可诊断失败信息，端到端脚本不伪造语义结果。

## 验收标准

1. OpenSpec 严格校验通过。
2. 每个脚本可从项目根目录按路径启动，自动创建隔离输出目录。
3. 解析脚本能够读取硬编码 PDF 并生成合法 v3 conversion JSON，输出质量报告摘要。
4. 依赖顺序脚本能够生成 chunks、SQLite、检索、重排和生成上下文文件。
5. 所有脚本打印退出状态、耗时和输出文件；失败时返回非零退出码且不吞掉异常原因。
6. 端到端脚本不会写入生产数据库或生产索引。
