## Context

`runtime/yolo_segmentation_runtime.py` 已为每个有效损伤项生成 `screening_severity`，其等级由损伤掩膜占当前影像面积的比例确定。主工作台的检测结果表当前只有四列，`on_image_done()` 也只把编号、类型、置信度和处理状态写入表格；底部虽然存在轻微/中等/严重图例，却没有逐行等级可供读取。

检测初筛等级与报告阶段 `damage-report.v3` 的视觉 AI 辅助等级是不同数据。检测页必须忠实显示前者，并通过列名和提示语保留“初筛、非安全鉴定”的边界。

## Goals / Non-Goals

**Goals:**

- 在检测结果表逐项显示已有 `screening_severity.level`。
- 提供稳定、集中、可测试的等级本地化映射。
- 对缺失、未知、无检出和失败结果进行保守显示。
- 让 CSV 导出与屏幕表格列保持一致。
- 保持按损伤类型筛选和现有主工作台布局可用。
- 让报告确认后的主按钮继续表达“工作流正在运行”，直到施工方案生成结束、失败或流程进入人工审核暂停点。
- 让检测结果“编号”在整个表格内连续递增，同时保持报告追溯使用的每图内部 `finding_index` 不变。
- 让已勾选的修复渲染在工程师确认 `hold` 方案后继续执行，同时明确它只是预览且不代表施工放行。

**Non-Goals:**

- 不修改 `affected-image-area-ratio` 的阈值和版本。
- 不调用报告视觉模型，不在检测页显示 `damage_level`。
- 不把初筛等级表述为结构安全、可靠性或危险性鉴定结论。
- 不改变检测结果 JSON 数据结构或历史结果文件。

## Decisions

### 使用检测结果中的 `screening_severity.level`

表格从每个 finding 的 `screening_severity.level` 读取等级。这是检测阶段已经生成并带规则版本的数据，可避免重复计算，也不会把报告阶段尚未生成或未确认的等级提前展示。

备选方案是根据 `area.area_ratio` 在 GUI 中再次计算。该方案会复制阈值、产生版本漂移，因此不采用。

### 使用集中映射函数并保守降级

GUI 内增加一个纯函数，把 `low`、`medium`、`high`、`undetermined` 分别映射为“轻微”“中等”“严重”“待判定”。输入缺失、大小写不同或未来出现未知值时统一显示“待判定”，不根据类别或置信度推断等级。

无损伤和失败占位行不是实际 finding，等级显示“—”。这样能区分“存在损伤但暂不能判级”和“没有损伤项可判级”。

### 将等级列放在置信度之后、状态之前

列顺序为“编号、损伤类型、置信度、损伤等级、状态”。它保留了原有前三列的阅读顺序，状态仍位于最右侧，同时与截图中的现有四列布局形成最小变化。

### CSV 与表格共用列顺序

导出逻辑扩展到五列，避免界面能看到等级而导出丢失。类型筛选继续读取第 2 列“损伤类型”，不受新增列影响。

### 报告确认后显式恢复运行态外观

自动报告生成结束、等待人工审核时，现有完成回调会把主按钮恢复为“启动”。当用户确认报告后，系统立即调度施工方案生成，但 `build_plan()` 只禁用按钮而没有恢复“停止”文字、停止图标和 `stopButton` 样式，造成状态语义错误。

报告确认分支和 `build_plan()` 入口都必须把主按钮设置为“停止”运行态外观；`build_plan()` 仍按现有合同禁用按钮，因为施工方案工作线程当前不支持安全取消。双重设置用于覆盖计时器调度前的短暂窗口和其他直接调用 `build_plan()` 的入口。施工方案成功、失败或进入后续人工审核时沿用现有终态处理。

备选方案是让施工方案线程立即支持取消。该方案涉及远程请求、中间文件和原子写入的取消合同，超出本次按钮状态修复范围，因此不采用。

### 展示编号与证据索引解耦

检测运行时的 finding `index` 是每张图片内部的零基索引，用于和图片名共同构成证据身份；它不适合作为跨图片结果表的用户编号。`on_image_done()` 插入每一行时使用插入前的 `rowCount() + 1` 作为展示编号，因此整张表稳定显示 `1..N`。

内部 finding 字典和批次摘要中的 `index` 不做任何修改，后续报告继续使用 `(image_name, finding_index)` 追溯证据。CSV 导出沿用表格展示编号。

### 将 `hold` 与“禁止生成预览图”解耦

当前演示施工方案的真实状态是 `review_status=confirmed_by_engineer`、`plan_status=hold`、`construction_released=false`。现有 `_construction_render_allowed()` 只接受 `pending_engineer_review`，因此勾选状态不会生效。

修复渲染属于非施工放行的概念预览。工程师已经确认方案后，`pending_engineer_review` 和 `hold` 都允许进入渲染；`hold` 仍表示现场施工、处置或采用具体工法前必须完成专项评估，且 `construction_released` 始终保持 `false`。`evidence_inconsistent` 继续阻断渲染，因为证据身份或内容不一致时生成图像可能对应错误对象或工法。

备选方案是所有方案状态都允许渲染。该方案会让证据不一致的方案也生成具有误导性的图像，因此不采用。

## Risks / Trade-offs

- [“损伤等级”可能被理解为正式鉴定等级] → 表头使用用户要求的“损伤等级”，同时为表头和等级单元格提供“影像面积比例初筛，非结构安全鉴定”的工具提示，并保留底部图例语境。
- [历史或测试数据没有 `screening_severity`] → 显示“待判定”，不抛出异常，也不推断等级。
- [五列挤压小尺寸窗口] → 继续使用伸缩表头，并通过离屏界面测试检查所有列存在、表格无逻辑错位；必要时对损伤类型列赋予更高伸缩权重。
- [“停止”可见但施工方案阶段暂不可点击] → 保持按钮禁用，并通过状态提示说明施工方案生成中；本次只纠正运行态视觉语义，不声称新增可取消能力。
- [筛选后可见行编号不连续] → 编号表示原始结果表顺序而不是当前筛选视图重排，筛选只隐藏行、不改编号，保证导出和恢复筛选后一致。
- [`hold` 预览被误认为可施工结果] → GUI 状态文案明确“仅供预览、仍保持暂停、尚未施工放行”，并保留 `construction_released=false` 和工程师确认门禁。

## Migration Plan

无需迁移已有 JSON。部署新 GUI 后，新旧检测结果均可读取：新格式显示实际初筛等级，缺少字段的旧结果显示“待判定”。回滚只需恢复 GUI 文件和对应测试，不影响检测产物。

## Open Questions

无。当前等级数据源、显示文案和异常降级策略均可从现有运行时合同确定。
