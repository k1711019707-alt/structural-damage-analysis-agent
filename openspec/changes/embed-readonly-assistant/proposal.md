# Proposal: 嵌入工程问答助手

## Why

当前 GUI 已经能够生成检测报告、施工方案并维护带范围的知识库，但用户需要在同一应用中继续追问当前结果、历史检测、知识库资料、公开网页和通用工程知识。问答入口需要像 Codex/OpenCode 一样保留多轮会话，同时必须保持工程证据可追溯，并禁止助手修改项目文件或执行命令。

## What Changes

- 在主窗口“设置”旁增加“问答助手”按钮，打开独立的 PySide6 对话框。
- 增加本地持久化会话记录，支持新建、继续、归档和导出对话。
- 增加只读上下文解析器，自动读取当前检测证据、报告、施工方案、知识库、联网结果和模型通用知识。
- 增加检测结果目录，使问题可以按日期、检测次数、输入路径、图片路径和报告/方案版本定位历史结果。
- 增加只读工具注册表；助手不暴露文件写入、删除、重命名、命令执行、配置修改或 RAG 激活工具。
- 增加流式回答事件、来源详情、证据哈希和不确定性记录。
- 对话正文仅显示用户与助手消息，不展示内部依据详情、来源清单或检索告警；这些信息继续保存在会话审计数据中。
- 知识库正文引用显示已核验的源文件名、章节/小节（如有）和 PDF 页码，不向用户暴露内部文档 ID；历史对话在来源可核实时回填引用。
- 面向用户和模型的助手名称统一为“工程问答助手”，只读权限继续由工具白名单强制执行。
- 复用现有 Responses Provider 与 `GenerationContext` 来源契约；OpenCode v2 仅借鉴/复用会话、流式事件和 Provider 设计，保留 MIT 许可声明，不引入其写文件或终端能力。

## Non-Goals

- 不实现文件编辑、报告覆盖、方案覆盖、知识库写回或任意 Shell/PowerShell/Python 执行。
- 不在本变更中替代专业工程师完成结构安全鉴定。
- 不把联网结果或模型通用知识冒充 `[KB:...]` 知识库证据。

## Impact

- 新增 `runtime/assistant/` 只读问答模块和会话存储。
- 主 GUI 新增入口和问答对话框。
- 用户数据目录新增 `assistant/conversations.sqlite3` 和只读检测结果目录缓存。
- 现有报告、方案、知识库和生成链路保持向后兼容。
