## Why

问答流被用户主动停止时，如果尚未收到文本，服务层会把空结果误判为“问答模型未返回文本”，界面因此显示 API 失败；同时生成期间禁用了“新建对话”，导致用户必须等待旧线程完全退出。用户主动取消应当是静默、正常的控制流，不应被解释为 API 故障。

## What Changes

- 将主动停止与模型/API 失败严格区分，停止时不触发“未返回文本”异常。
- 停止后丢弃本轮所有待显示和已流式显示的助手内容，不保存失败消息或取消消息。
- 用户点击停止后立即恢复新建和切换对话能力，无需等待后台流完全结束。
- 将运行中的请求绑定到发起它的会话，防止旧请求完成/失败信号写入后来新建或切换的会话。
- 保留用户已经发送的问题；只移除本轮未完成的助手输出。

## Capabilities

### New Capabilities

- `assistant-cancellation`: 定义问答流的静默取消、立即恢复会话导航以及跨会话回调隔离。

### Modified Capabilities

无。

## Impact

- 修改 `runtime/assistant/service.py` 的取消返回顺序。
- 修改 `runtime/assistant/dialog.py` 的请求归属、停止状态和回调处理。
- 扩充 `tests/test_readonly_assistant.py`，覆盖零文本取消、部分文本取消、新建对话和迟到回调。
- 不修改 API 配置、知识库、报告/方案文件或会话数据库结构。
