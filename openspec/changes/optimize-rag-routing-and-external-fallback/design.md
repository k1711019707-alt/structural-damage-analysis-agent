## Context

当前混合检索把词法、语义、精确标识符和来源标题候选放入同一 RRF 排名后直接截断。首轮 150 题评测中，词法 Hit@30 为 57.14%，混合仅 47.86%；自然语言改写更依赖语义通道，而精确条款、数字和表格题更依赖结构化词法。来源标题 exact 权重为 12，且可向同一文档的大量 chunk 传播。层级模式即使对简单问题也可能水合 parent/同标题块，增加 P95 延迟但不改变 direct 排名。

生成链目前只接受知识库证据，并在证据未知时警告。用户已明确授权知识库无答案时优先联网搜索、联网不可用时根据模型训练知识回答，但外部内容不得伪装为 `[KB:...]` 证据，工程高风险结论仍需人工复核。

## Goals / Non-Goals

**Goals:**

- 使用可解释、确定性的查询特征选择检索权重、保留配额和层级策略，不读取 Gold 标签。
- 在最终 Top-K 前合并各通道保留集，使新增混合方案的深层召回不再被统一截断破坏。
- 降低标题通道对 scope 内正文排序的影响，同时保持标题用于文档路由的价值。
- 只在多证据/风险条件问题或直接证据不足时扩展层级上下文，并限制扩展预算。
- 让生成链明确区分知识库、真实 Web Search 和模型一般知识三种来源。
- 在独立 `evaluation_v2` 中用固定快照重新运行并报告真实数据。

**Non-Goals:**

- 不修改 Gold 标签、SQLite、语义 NPZ、原 PDF、活动生产 manifest 或旧 `evaluation_v1`。
- 不声称 provider 具备 Web Search，除非运行时能力检测通过且实际返回可验证网页来源。
- 不把模型一般知识或网页摘要写成知识库 citation。
- 不以 benchmark 题型标签作为线上查询分类输入。

## Decisions

1. **确定性查询路由。** 新增公开可测试的分类函数，根据标准号/条款格式、表格词、数字单位、否定/条件词、问法长度与口语改写特征返回 `QueryRoute`。路由只调整权重、配额、标题先验和层级策略，不直接决定答案。
2. **保留式候选 union。** 词法、语义和 exact 通道分别保留 bounded Top-N，按 chunk 去重后计算融合分；exact 命中强制进入候选池。最终输出仍服从 `top_k`，从而兼容旧 API。相比简单增大统一 `candidate_k`，该方案能明确防止某一通道垄断候选。
3. **标题是 scope 信号而非正文相关性替代。** 未指定 scope 时标题可帮助定位文档，但仅提供小额先验；已显式提供 `document_ids` 时不把标题 exact 分传播给文档内所有 chunk。标准号/条款 exact 通道保持独立高优先级。
4. **层级门控分离 direct ranking 与 context assembly。** `off/auto/forced` 策略控制 parent/同标题扩展。`auto` 对精确标识符、单值数字和简单表格查询默认关闭；对风险条件、多证据或 anchor 不足的查询开启，并限制每 anchor 和总字符/块预算。direct 指标继续只看 anchors。
5. **显式回答来源状态机。** 检索证据充分时为 `knowledge_base`；知识库无答案且 Web Search 能力可用时为 `web_search`；否则为 `model_prior`。Web Search 必须携带 URL/标题/访问时间等可核验来源，未获得来源不得标为成功。模型一般知识必须附固定非 KB、可能过时、需复核警告。
6. **能力注入而非假定联网。** 生成/运行时接收可选外部搜索 provider/capability；默认无网络能力时稳定回退到 `model_prior`。测试使用 fake provider 验证合同，避免读取或暴露凭据。
7. **evaluation_v2 保留历史可比性。** 继续报告旧词法、纯语义、旧混合，并增加自适应混合、重排和门控层级配置。原 10 条 `expected_no_answer` 解释为 `expected_kb_no_answer`，评估正确外部回退路由而非强制拒答。

## Risks / Trade-offs

- [规则分类不能覆盖所有自然语言] → 输出路由诊断并保留 `general` 均衡策略，使用题型分层结果继续校准。
- [通道保留增加候选和延迟] → 对每通道设置上限，在 union 后统一重排并报告 P50/P95。
- [降低标题权重可能损失文档发现] → 未显式 scope 时保留弱标题先验，并用文档级匹配而非全 chunk 强加分。
- [层级门控漏掉必要背景] → 支持 `forced`，`auto` 在 anchor 不足/风险条件/多证据查询时开启，并单报上下文覆盖。
- [Web Search provider 能力不确定] → 真实调用前做能力检测；失败或无可核验来源时转 `model_prior`，不伪造联网结果。
- [模型一般知识可能错误或过时] → 强制来源模式标签、时效警告与工程人工复核标识。

## Migration Plan

1. 为新增路由和来源字段提供默认值，保持旧调用方行为可运行。
2. 先增加单元/合同测试，再修改检索和生成链。
3. 在只读 Gold/SQLite/NPZ 上生成独立 `evaluation_v2`。
4. 对 focused tests、完整回归和 OpenSpec 做严格校验。
5. 若新路由不满足深层召回或延迟门槛，保留旧模式可选并删除/另存 `evaluation_v2`；无需回滚数据资产。

## Open Questions

- 当前远程 Responses provider 是否在实际部署配置中支持 `web_search` 工具，需要通过不暴露凭据的能力检查和真实来源返回验证；在此之前只承诺合同与安全回退。
