# Proposal: 优化工作台底部状态区窗口比例

## 背景

主工作台底部状态区目前使用固定 stretch 比例 `2:3:6:3`，在宽屏下事件日志占用空间偏大，而处理状态和修复施工方案预览的可读宽度不足；在较窄窗口下各面板也容易出现内容拥挤。

## 目标

- 调整红框状态区四个面板的空间分配，使处理状态、修复施工方案预览、事件日志和操作区的比例更均衡。
- 保留现有面板、信号连接、按钮行为和响应式滚动机制。
- 为比例建立可回归的几何约束，避免后续修改再次造成底部区域失衡。

## 非目标

- 不改变识别、报告生成、施工方案生成或渲染业务逻辑。
- 不改变主工作台上方任务队列、影像预览、检测结果和项目概括区域。
- 不修改配色、文案或数据模型。

## 验收标准

1. 在 1680×980 和 1440×980 窗口下，底部四个面板均可见，方案预览保持至少可读的横向空间，事件日志不再独占过大的比例。
2. 在 1280×720 低高度窗口下，底部操作区仍能通过工作台滚动区域访问。
3. 现有 GUI 合同和视觉冒烟测试保持通过，并新增比例回归断言。
