# Proposal: 准备 RAG 基准数据集与检索问答基准集

## 目标

- 建立一套可追溯的文档解析/切片/索引基准清单。
- 建立一套带相关文档、chunk、查询类型和范围约束的检索问答基准集。
- 样本优先引用当前生产 v2 数据库中的真实文档与 chunk，不凭空生成来源标识。
- 明确人工复核字段与自动生成字段，避免把自动命中当作最终标注。

## 范围

- 输出目录：`benchmarks/rag/`。
- 文档基准：源文件、文档 ID、解析状态、页数、chunk 统计、警告页和建议抽样页。
- 检索基准：标准号、条款号、自然中文、同义词、表格/跨页、无答案、范围隔离、高风险边界查询。
- 提供生成脚本，允许在生产库更新后重新生成并保留数据库哈希和生成时间。

## 非目标

- 不修改生产数据库、源 PDF 或运行时检索逻辑。
- 不把自动生成的候选 chunk 直接宣称为人工金标准；候选标注必须带 `annotation_status`。
- 不启用当前未激活的语义 sidecar。

## 验收标准

1. 基准文件包含真实的生产库文档和 chunk 标识，并能通过脚本重新生成。
2. 检索问答集覆盖至少 8 类查询场景，包含范围隔离和无答案样本。
3. 每条查询包含 `relevant_documents`、`relevant_chunk_ids`、`query_type`、`difficulty`、`annotation_status`。
4. OpenSpec 严格校验通过，生成脚本可在当前项目解释器下运行。
