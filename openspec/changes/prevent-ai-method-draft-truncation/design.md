## Context

施工方案远端草稿原先只扩写描述字段，五项损伤拆成 3+2 两批即可控制长度。现在每个分项新增工法名称、具体修复方法和工法理由，真实第一批响应增长到 20625 个字符后被兼容网关截断。损伤分析报告仅在超过八项时分批，同样可能因单次总输出过长而截断。服务虽能安全回退，但用户得到的不是远端 AI 内容。

## Goals / Non-Goals

**Goals:**

- 使损伤分析报告和施工方案都能稳定获得完整、严格校验的 AI 分项草稿。
- 将每个远端响应限制为一组有硬上限的字段，消除总方案长度对单次响应长度的影响。
- 保持累计流式预览、身份顺序、引用校验和确定性合并。
- 保持任何失败均可审计、凭据脱敏并回退到本地保守方案。

**Non-Goals:**

- 不接受或修补截断 JSON。
- 不放宽严格 schema 或身份对应校验。
- 不改变远端 URL、模型、密钥、超时和重试配置。
- 不修改 RAG/Docling 或图像渲染协议。

## Decisions

### 两个阶段均按单个损伤生成

损伤分析报告不再以八项为分批阈值，而是每次只请求一个 `ReportFinding`，最终总体等级、完整性和摘要由本地按全部已验证分项确定性组装。施工方案也每次只请求一个完整 `ConstructionWorkItemDraft`，各次返回的总体字段按现有首项和去重规则合并。总长度随损伤数量增加时只增加有界请求数量。

### Schema 硬限制保证单次响应有确定上界

所有远端可写字符串设置非空和 `maxLength`，所有列表设置 `maxItems`，列表元素也设置 `maxLength`。工法正文、理由和步骤允许更大的业务合理上限，其余条目采用短句上限。这样单次 JSON 的理论最大尺寸低于本次已知网关截断点。总方案可以包含任意数量损伤，因为新增损伤只增加固定数量的有界请求，不增加任一请求的最大尺寸。

### 本地确定性组装完整报告和方案

每份报告分项和施工分项必须具有正确的 `image_name/finding_index`，本地按识别结果及确认报告顺序组装。报告总体等级按最不利的规范化分项等级确定；施工方案总体字段沿用第一份草稿并对后续通用列表稳定去重。任何遗漏、重复、增加或换序均被拒绝。

施工方案每次请求还会把本次上下文允许使用的 `source_marker` 写入动态 JSON Schema 枚举。顶层和分项引用只能选择这些精确标记；没有知识片段时引用列表强制为空。本地仍执行第二次引用校验，未知页码范围或模型自造标记不会进入最终方案。

### 提示词约束简洁而不削弱工程内容

要求模型避免重复报告原文，每个列表只提供必要且不重复的条目，工法正文聚焦可执行步骤、适用条件和现场核验边界。该约束用于减少无界输出，不删除质量、安全、验收或风险字段。

### 原子输出预算保持 16000 token

每个原子请求使用 16000 token 的应用预算，但正确性不依赖网关兑现该预算，因为 schema 的字段长度和列表数量已经从内容侧限制最大响应。严格验证失败时继续走现有回退。

## Risks / Trade-offs

- [远端请求次数增加] -> 报告和方案均为每项调用一次，沿用现有重试和累计预览；可靠完整输出优先于少量调用。
- [字段硬上限压缩内容] -> 上限覆盖工程审核所需的合理篇幅，要求短句分点；超长叙述不属于施工草案的有效结构化内容。
- [模型违反 schema 上限] -> 严格验证拒绝该原子草稿并走可审计回退，不接受截断或部分 JSON。
- [部分批次成功、后续批次失败] -> 不持久化部分远端方案，整份方案回退，避免混合来源难以审核。

## Migration Plan

无需迁移 schema 或历史文件。更新后重新从已确认损伤报告生成施工方案，即可覆盖现有 `local_fallback` 方案。回滚只需恢复原分批大小；历史审计文件保持可读。

## Open Questions

无。真实验收使用用户本机已配置的远端服务执行五项施工方案生成，但不输出或持久化密钥。这里保证的是总方案可任意扩展且单次响应有硬上界；任何外部服务完全不可用时仍只能回退。
