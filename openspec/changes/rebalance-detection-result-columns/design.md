## Context

当前检测结果表共有“编号、损伤类型、置信度、损伤等级、状态”五列，但没有直接显示来源图片文件名。实现还把损伤类型设为唯一的 `QHeaderView.Stretch` 列，其余列使用 `ResizeToContents`。空表时短表头只需要很小宽度，所有剩余空间都进入损伤类型列，造成截图中列宽明显失衡；有长数据时列宽还会随内容变化。

## Goals / Non-Goals

**Goals:**

- 在编号之后显示来源文件名，使每条结果无需打开详情即可追溯到图片。
- 在空表和有数据两种状态下维持一致的六列比例。
- 随表格视口宽度响应式计算像素宽度。
- 让短字段获得足够空间，同时显著缩小损伤类型列。
- 在项目支持的宽、窄窗口尺寸下无表头重叠和横向滚动。

**Non-Goals:**

- 除新增文件名外，不改变现有结果字段的内容和相对顺序。
- 不改变主工作台三个顶部面板的 `1:3:3` 比例。
- 不增加用户拖动列宽后的持久化设置。

## Decisions

### 使用专用比例表格控件

增加一个轻量 `ProportionalTableWidget`，构造时接收总和为 1 的列宽权重。控件在 `resizeEvent` 中读取 `viewport().width()`，按权重设置固定列宽，最后一列吸收四舍五入余量。

相比在主窗口 `_apply_responsive_layout()` 中设置宽度，控件级处理可以覆盖同一布局缩放档位内的连续尺寸变化，也能复用于备用识别页，不依赖主窗口定时器或签名缓存。

### 文件名直接来自 `on_image_done()` 的图片名称

实际损伤行、未检出占位行和处理失败行均使用 `on_image_done(name, result)` 的 `name` 参数填充“文件名”。该值与任务队列和 `result.image_name` 的来源一致，不从路径字符串重新解析，也不改变内部证据身份。文件名单元格提供完整文本工具提示，较窄窗口下即使省略显示也可查看全名。

新增文件名后，损伤类型筛选列索引从 1 调整为 2；CSV 按界面顺序导出六列。

### 采用 9:21:26:14:16:14

编号使用 9%；新增文件名使用 21%；损伤类型降至 26%，仍是最宽单列；置信度、等级和状态分别使用 14%、16%、14%。该比例让文件名和类型共同承担主要信息宽度，同时为三个短字段保留稳定空间。文件名和损伤类型单元格均提供完整文本工具提示。

### 固定模式而非内容驱动模式

所有六列使用 `QHeaderView.Fixed`，避免 `ResizeToContents` 因行内容变化导致布局跳动。窗口缩放时控件自动重算，因此“固定”只表示当前视口内禁止内容驱动重排，不表示固定像素值。

## Risks / Trade-offs

- [极窄窗口下四字表头可能接近边界] → 在项目最小支持视口进行截图和几何测试，“损伤等级”在三个短字段中获得最高的16%份额。
- [长文件名或英文损伤类型可能省略] → 两列分别获得21%和26%，并用单元格工具提示暴露完整内容，不再挤压其他字段。
- [像素取整导致比例微小偏差] → 最后一列吸收余量，测试使用小范围容差而非要求绝对相等。

## Migration Plan

无数据迁移。部署后列宽仅影响显示；回滚时恢复原表头 resize mode 即可。
