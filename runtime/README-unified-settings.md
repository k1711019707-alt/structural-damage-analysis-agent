# 统一设置、知识库与文档输出

## GUI 视觉重构

主工作台采用无顶部流程导航的三栏工程控制台布局；设置窗口采用左侧垂直导航和右侧内容面板。视觉参考稿位于 `artifacts/gui-redesign/`。主界面和设置页使用 Qt 标准线性图标，缺少平台图标时由 Unicode/文字降级，不影响功能。

已在 `YOLO11-HAI` 环境使用 Qt 离屏平台验证 1680×980 主界面和 1180×800 设置页。实际截图为 `artifacts/gui-redesign/actual-main-workbench-1680x980.png` 和 `artifacts/gui-redesign/actual-settings-knowledge-base-1180x800.png`。应用启动时会显式注册系统中可用的 Noto Sans SC/微软雅黑中文字体，避免 Qt 离屏或简化部署环境出现中文方框。

新增模块：

- `settings_models.py`：版本化 API、知识库、损伤分析报告/施工方案生成档案、模板和 provenance 契约。
- `settings_store.py`：`gui_settings.json` 原子保存、密钥遮罩导出和旧 `gui_api_config.json` 迁移。
- `knowledge_base.py`：PDF/DOCX 抽取、DOC 明确不支持提示、多级文件夹分类、资源管理器式新建/重命名/移动/删除、分块和本地 SQLite FTS 检索。
- `generation_context.py`：统一组合结构化证据、提示词和带来源标记的知识库片段。
- `document_templates.py`：DOCX 元数据/占位符校验和安全降级渲染。
- `damage_repair_plan.py`：依损伤证据建立不含金额的修复工法、施工范围和渲染对象筛选。

首版文件支持：参考资料支持 `.pdf`、`.doc`、`.docx`；其中 `.doc` 需要本机转换器，模板仅支持 `.docx`。损伤分析报告与施工方案分别维护自己的一级文件夹多选、提示词和 Word 模板；“修复渲染图”维护 FHL/硅基流动供应商配置与共用提示词，主流程提供启用/停用开关。新流程不再包含造价预估，不产生金额、单价、合计或 `repair_plan_cost.json`。扫描 PDF OCR、宏和任意脚本不在支持范围内。

报告模板可使用 `{{image_surface}}`、`{{image_mask}}` 和 `{{image_measurement}}` 槽位。识别完成后，程序会保存原图、分割覆盖图和带像素标注的尺寸图，并将首个完整成功样本以内嵌图片方式写入 DOCX；生成清单记录每个槽位的来源和插入状态。主界面的“报告文件”栏可以在本机 Word 中打开生成的 DOCX 继续编辑，也可只读预览选定 DOCX 或文字型 PDF。尺寸图仅显示像素证据，未标定时不会生成毫米数值。

上传 Word 模板时，程序会校验后复制到项目 `templates` 目录，并且设置只记录该受管副本的哈希和路径；同名不同内容会以哈希后缀分开保存。知识库导入同样会把 `.pdf`、`.doc` 或 `.docx` 副本保存到知识库根目录的 `source_files`，再建立索引。两个流程都不会修改或删除用户选择的原始文件。旧设置若仍指向不存在的外部模板，会在“报告文件”栏和 `generation_manifest.json` 显示失败原因；重新上传一次模板即可迁移。

主工作台的检测结果表仅显示“编号 / 损伤类型 / 置信度 / 状态”，不在表格中显示严重度、位置或面积。这些结构化证据仍保留在后台结果中，可供报告与施工方案生成使用。

默认且唯一的生产 YOLO 模型为 `models/best.pt`，GUI、CLI、启动诊断、引擎导出配置和开发打包 PT 来源使用同一正式权重；运行时不再搜索训练 run、基线或 smoke 模型。

报告生成对上游短时故障具有容错：5xx、429、超时和连接错误最多进行 3 次总尝试。持续失败时，系统根据结构化检测证据生成 `local-evidence-fallback` 降级报告，并继续施工方案和可选渲染阶段。空知识库会直接跳过检索，大型 JSON 查询会限制为 24 个有效关键词，避免 SQLite 表达式过大。

知识库页面按资源管理器逻辑组织：左侧是可新建子文件夹、重命名和递归删除的目录树，右侧以“名称 / 类型 / 大小 / 状态 / 来源位置”列表展示资料。可多选删除知识库记录、双击打开原始文档；删除操作始终保留电脑上的原始文件。

运行依赖由部署环境提供：PySide6（GUI）、pypdf（PDF 文本抽取）、pydantic/openai（现有报告服务）以及模型推理依赖。知识库和模板核心模块本身只使用 Python 标准库与 SQLite；缺少可选解析库时会记录可操作的失败状态。

回滚方式：删除或停用 `gui_settings.json` 后，现有 `gui_api_config.json` 仍可被迁移读取；关闭设置页中的知识库和模板选择即可继续生成原有 JSON/Markdown 产物。原始文件、旧配置和既有输出不会被删除。
